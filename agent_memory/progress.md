11. **WebView2 占用优化（2026-11-21 已测基线 + 试过挂起后回退，方案待拍板）**：单实例（正式版 `v0.7.2`）合计 **WS ≈ 518MB / Private ≈ 338MB**，8 个进程：app 48.6、WebView2 browser 123.5(+12.1)、utility 37.3+19.2、GPU 106.5、渲染进程（主窗口）112.8、渲染进程（**快捷键提示浮窗 560×56，隐藏时常驻**）58.2。开发版实例同构 ≈ 571MB / 342MB（主窗口渲染 126.6、提示浮窗渲染 79.3、GPU 119）。
    - 更正：此前把第二个常驻渲染进程记成「剪贴板弹窗」，实际是**快捷键提示浮窗**（矩形 560×56 可辨认）；剪贴板弹窗是关窗即销毁，不常驻。
    - 关键事实：① **窗口隐藏不释放**——主窗口 `WM_CLOSE` 隐藏到托盘后渲染进程只掉 1.7MB；提示浮窗隐藏后整份渲染进程还在；② 空闲 60 秒无回落（±0.7MB，CPU +0.1–0.3s），没有泄漏但也不主动收；③ 强杀测试留下 6 个无主 `msedgewebview2.exe` 残留，合计 ~175MB（正常托盘退出不会）。
    - **已试「隐藏即挂起」并回退**：用 `ICoreWebView2_3::TrySuspend/Resume`（新增依赖 `webview2-com = "0.38"`）接在主窗口隐藏/唤出路径，实测主窗口隐藏后渲染进程只有 **WS −3.1MB / Private −3.8MB**，CPU 无可测变化（Chromium 对不可见渲染器本来就节流），收益在噪声内，且挂起期间页面不处理事件；已 `git checkout` 还原，未提交。
    - 结论：**挂起不是这块的答案**。真正的可动项是「提示浮窗渲染进程 58–79MB」（原生化或空闲销毁）与「主窗口渲染进程瘦身」；browser/GPU/utility ≈ 300MB 是 WebView2 固定成本。

    - **结论（2026-11-22，已定稿，勿再当优化点重提）**：停用工具**不会**回收 WebView2 的固定成本（browser≈123MB + GPU≈107MB + utility≈56MB）与主窗口渲染进程（≈113MB）；只有当该工具拥有**独立 WebView2 窗口**时，停用销毁该窗口才可能回收其渲染进程（历史上快捷键提示浮窗隐藏常驻 ≈58MB，已随写入化原生浮窗消除）。隐藏/挂起主窗口只回收 1.7–4MB，收益在噪声内。
